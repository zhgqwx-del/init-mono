# 交付与复盘

先读任务规格、计划、验证回执和各仓当前 Git 状态。核对受测 SHA、未提交内容、各仓 PR 及它们的依赖。用 scripts/mono.py check 需求号 确认已有证据是否覆盖当前代码与规格。用户要求交接时，即使仍有失败或未完成项，也应把实际状态、负责人和下一步完整交接。

在 delivery.md 汇总本次行为变化、受测版本、证据、人工判断与剩余限制。已要求上线时按既有规则准备或执行合并、发布和灰度，写明先后顺序、兼容窗口、冒烟与监控、停止条件、恢复动作及有权限的负责人。遵循当前任务授权和项目权限。

记录人工投入、周期、交接等待、返工与质量表现，可获取时记录模型成本。把可复用的业务或架构决定写入 docs/mono/decisions.md，更新发生变化的系统入口及运行手册，并保留任务来源。留下简短接手说明。清理工作树前核对改动已保存及后续是否仍需要该工作树。
