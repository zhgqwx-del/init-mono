# 联合验收

读任务的 task.json、task.md、plan.md、projects.json 与 docs/mono/operations.md。先确认需求涉及的每个项目、测试数据和环境，再执行现有仓内测试和跨项目流程。对每条 AC 用真实输入和断言验证可观察结果。结合实际规格覆盖缺省、非法输入、分页、兼容、数据范围或其他相关边界。

用 scripts/mono.py run 需求号 --ac AC01 --cwd 目录 -- 命令 参数 保存运行回执。只有被该命令实际断言覆盖的编号才传 --ac，一个命令可以覆盖多个判据。服务启动、环境探测或没有业务断言的命令可保存回执但无需关联 AC。该脚本能给任意已授权的项目测试命令留存输出和版本，不代替编写或理解测试。

把每条实际结果和回执路径写入 verification.json。未执行、缺环境或失败的条目如实保留为 pending 或 failed。用 scripts/mono.py check 需求号 核对全部结果和当前规格、代码内容。规格或代码有变化时复跑受影响用例，基于新的回执更新关联。

界面截图、接口响应、日志等作为证据补充保存。实际执行的命令回执用于版本核对。有条件时由独立验证者复跑关键流程。向负责人报告结果、覆盖限制、失败和所需判断，人工确认写入 human_decision。完成后按用户要求继续交付或使用 mono-wrap 准备交接。

存在仓内 STDD/SDD 流程时，通过 status 找到各仓的变更，遵循其 test-report 和测试入口。仓内 verification.md 记录该项目结果。Mono 验收报告额外记录跨项目的真实调用、匹配的三方版本和证据位置。
